# Agent usage for Herdr

TypeScript sources live in `mods/token-usage/src/`. Herdr runs the generated root-level JavaScript directly. Keep the generated JS when installing or sharing this mod; never edit it by hand. Python readers and `tap.sh` are runtime sources, not build outputs.

## Change and verify

From `mods/token-usage/`:

```sh
npm ci
npm run verify
```

`verify` checks all TS, checks the core with strict null checks, rebuilds JS, runs the Node and Python regression suites, and runs `herdr-app check`. Source errors prevent emission. `npm test` rebuilds first so it cannot silently test stale JS. After changing native layout or deferred render paths, also inspect the running app with `herdr-app shot` and check `herdr-app status`.

`gpui-kit.d.ts` is generated by the installed Herdr and is the runtime contract. Do not pin or edit it. The view's TS config follows Herdr's init-time field lifecycle (`strictNullChecks: false`); `types`, provider decoders, refresh state, and display models additionally pass `tsconfig.core.json` with strict null checking enabled.

## Where changes belong

| Change | Source |
|---|---|
| Shared usage/account shapes, supported actions | `src/types.ts` |
| Provider response normalization and validation | `src/providers.ts` |
| Single-flight refresh and last-good-value handling | `src/resource.ts` |
| Labels, stale state, common-period comparison | `src/usage-model.ts` |
| Herdr view lifecycle, rendering and commands | `src/main.ts` |
| Claude statusline connection and transcript reading | `src/data.ts`, `tap.sh` |
| Codex CLI status parsing, safe output filtering | `read_codex_account.py` |
| Codex log reading and metadata cache | `read_codex_usage.py` |

Both providers implement `UsageProvider`: `readUsage`, `readAccount`, and login/logout commands. The view does not guess Codex's schema or parse CLI output. Account state is a discriminated union (`signed-in`, `signed-out`, `unavailable`); read errors are separate from account identity. Unsupported responses fail explicitly. The generic account renderer displays optional identity fields only when supplied. Claude's statusline connection stays provider-specific.

## Runtime and performance contracts

- Resource refresh is single-flight per view: concurrent consumers share the pending read. A failed read preserves the last good value and exposes an error; a successful signed-out result replaces a signed-in result.
- Claude authentication is cached for five minutes in the usage strip; usage/connection refresh every ten seconds. Codex usage refreshes every fifteen seconds. Account status is polled every ten seconds only while its account page is open. Session transcripts refresh only on the Usage page.
- Codex scans at most eight daily folders and reads at most 24 recent rollouts, up to 2 MiB each. Unchanged files reuse cache entries keyed by nanosecond mtime and size. Cache writes are atomic, with unique temporary files; a cache write failure never hides valid usage.
- The cache stores sanitized usage samples only, under Herdr's `data/token-usage/codex-cache.json`. Readers do not open auth files or expose CLI output that could contain an API key.
- Limits are local snapshots after replies. Switching accounts can leave an earlier report until a new reply. Unknown/missing limits are never filled with invented values.
- `checking()` prevents helpers and writes during Herdr's initial-render check. Tests use fixtures and local temporary files, never login, logout, or a live account mutation.

## Extending providers

Extend `ProviderId` and the `createProviders` registry, implement `UsageProvider`, then add contract fixtures in `tests/providers.test.js`. Normalize all external values before returning `UsageReport` or `AccountState`; do not add provider schema checks to row rendering. Add a settings page only when there is a real new interaction. Native account actions must continue through the user's own CLI and confirmation flow.
